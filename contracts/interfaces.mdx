## Overview

The COWFeeModule contract interacts with several external contracts through well-defined interfaces. This page provides complete documentation for all interfaces used in the project.

## IERC20

**Source:** `src/interfaces/IERC20.sol`

Minimal ERC20 token interface containing only the functions required by the COWFeeModule.

```solidity
interface IERC20 {
    function approve(address, uint256) external;
    function balanceOf(address) external view returns (uint256);
    function transfer(address, uint256) external;
}
```

### Functions

#### approve

```solidity
function approve(address spender, uint256 amount) external
```

Allows `spender` to withdraw from the caller's account multiple times, up to the `amount`.

<ParamField path="spender" type="address" required>
  Address authorized to spend tokens
</ParamField>

<ParamField path="amount" type="uint256" required>
  Maximum amount the spender can transfer
</ParamField>

<Note>
  The COWFeeModule uses `type(uint256).max` for unlimited approvals to the vault relayer.
</Note>

#### balanceOf

```solidity
function balanceOf(address account) external view returns (uint256)
```

Returns the token balance of the specified account.

<ParamField path="account" type="address" required>
  Address to query balance for
</ParamField>

**Returns:** `uint256` - The token balance

#### transfer

```solidity
function transfer(address to, uint256 amount) external
```

Transfers tokens from the caller to the recipient.

<ParamField path="to" type="address" required>
  Recipient address
</ParamField>

<ParamField path="amount" type="uint256" required>
  Amount of tokens to transfer
</ParamField>

## IWrappedNativeToken

**Source:** `src/interfaces/IWrappedNativeToken.sol`

Interface for wrapped native token contracts (e.g., WETH). Extends IERC20 with deposit functionality.

```solidity
interface IWrappedNativeToken is IERC20 {
    function deposit() external payable;
}
```

### Functions

#### deposit

```solidity
function deposit() external payable
```

Wraps native tokens (e.g., ETH) into wrapped tokens (e.g., WETH). The amount wrapped equals `msg.value`.

<Note>
  The COWFeeModule uses this function to convert native token balances held by the settlement contract into wrapped tokens before transferring to the receiver.
</Note>

**Usage in COWFeeModule:**
```solidity
// Wraps native tokens when balance >= minOut
approveAndDripInteractions[len - 2] = IGPv2Settlement.InteractionData({
    to: wrappedNativeToken,
    value: nativeBalance,
    callData: abi.encodeCall(IWrappedNativeToken.deposit, ())
});
```

## ISafe

**Source:** `src/interfaces/ISafe.sol`

Interface for Safe (formerly Gnosis Safe) wallet contracts. Provides module execution capabilities.

```solidity
interface ISafe {
    enum Operation {
        Call,
        DelegateCall
    }

    function execTransactionFromModuleReturnData(
        address to,
        uint256 value,
        bytes memory data,
        Operation operation
    ) external returns (bool success, bytes memory returnData);

    function enableModule(address module) external;
}
```

### Enums

#### Operation

```solidity
enum Operation {
    Call,        // Regular call
    DelegateCall // Delegate call
}
```

Defines the type of operation to execute.

<Warning>
  COWFeeModule only uses `Operation.Call`. DelegateCall is not used and would be dangerous as it executes code in the Safe's context.
</Warning>

### Functions

#### execTransactionFromModuleReturnData

```solidity
function execTransactionFromModuleReturnData(
    address to,
    uint256 value,
    bytes memory data,
    Operation operation
) external returns (bool success, bytes memory returnData)
```

Allows an enabled module to execute a transaction from the Safe.

<ParamField path="to" type="address" required>
  Target contract address
</ParamField>

<ParamField path="value" type="uint256" required>
  Amount of native tokens to send with the transaction
</ParamField>

<ParamField path="data" type="bytes" required>
  Encoded function call data
</ParamField>

<ParamField path="operation" type="Operation" required>
  Type of operation (Call or DelegateCall)
</ParamField>

**Returns:**
- `success` (bool) - Whether the transaction executed successfully
- `returnData` (bytes) - Return data from the executed transaction

<Note>
  COWFeeModule's `_execFromModule` function wraps this call and reverts on failure.
</Note>

#### enableModule

```solidity
function enableModule(address module) external
```

Enables a module for the Safe, allowing it to execute transactions.

<ParamField path="module" type="address" required>
  Address of the module to enable
</ParamField>

<Warning>
  This function must be called by the Safe itself (through a Safe transaction) before the COWFeeModule can operate. The module will not function until enabled.
</Warning>

## IGPv2Settlement

**Source:** `src/interfaces/IGPv2Settlement.sol`

Interface for the CoW Protocol (Gnosis Protocol v2) settlement contract. This is the core contract that handles order settlement and execution.

```solidity
interface IGPv2Settlement {
    struct OrderData { ... }
    struct TradeData { ... }
    struct InteractionData { ... }

    function settle(...) external;
    function setPreSignature(bytes calldata orderUid, bool signed) external;
    function domainSeparator() external view returns (bytes32);
    function vaultRelayer() external view returns (address);
}
```

### Structs

#### OrderData

```solidity
struct OrderData {
    address sellToken;
    address buyToken;
    address receiver;
    uint256 sellAmount;
    uint256 buyAmount;
    uint32 validTo;
    bytes32 appData;
    uint256 feeAmount;
    bytes32 kind;
    bool partiallyFillable;
    bytes32 sellTokenBalance;
    bytes32 buyTokenBalance;
}
```

Defines a complete CoW Protocol order.

<ParamField path="sellToken" type="address">
  Token to sell
</ParamField>

<ParamField path="buyToken" type="address">
  Token to buy
</ParamField>

<ParamField path="receiver" type="address">
  Address to receive bought tokens
</ParamField>

<ParamField path="sellAmount" type="uint256">
  Amount of sell tokens
</ParamField>

<ParamField path="buyAmount" type="uint256">
  Amount of buy tokens (minimum for sell orders)
</ParamField>

<ParamField path="validTo" type="uint32">
  Unix timestamp when order expires
</ParamField>

<ParamField path="appData" type="bytes32">
  Application-specific data
</ParamField>

<ParamField path="feeAmount" type="uint256">
  Fee amount (0 for this module)
</ParamField>

<ParamField path="kind" type="bytes32">
  Order kind (sell or buy)
</ParamField>

<ParamField path="partiallyFillable" type="bool">
  Whether order can be partially filled
</ParamField>

<ParamField path="sellTokenBalance" type="bytes32">
  Source of sell tokens (erc20/external/internal)
</ParamField>

<ParamField path="buyTokenBalance" type="bytes32">
  Destination for buy tokens (erc20/external/internal)
</ParamField>

#### TradeData

```solidity
struct TradeData {
    uint256 sellTokenIndex;
    uint256 buyTokenIndex;
    address receiver;
    uint256 sellAmount;
    uint256 buyAmount;
    uint32 validTo;
    bytes32 appData;
    uint256 feeAmount;
    uint256 flags;
    uint256 executedAmount;
    bytes signature;
}
```

Represents a trade to be executed in a settlement.

<Note>
  COWFeeModule passes empty TradeData arrays since it only uses the settlement contract for pre-signatures and interactions, not direct trading.
</Note>

#### InteractionData

```solidity
struct InteractionData {
    address to;
    uint256 value;
    bytes callData;
}
```

Defines an arbitrary contract interaction to execute during settlement.

<ParamField path="to" type="address">
  Target contract address
</ParamField>

<ParamField path="value" type="uint256">
  Native tokens to send with the call
</ParamField>

<ParamField path="callData" type="bytes">
  Encoded function call data
</ParamField>

<Note>
  COWFeeModule uses interactions for:
  - Token approvals to vault relayer
  - Setting pre-signatures for orders
  - Wrapping native tokens
  - Transferring wrapped tokens
</Note>

### Functions

#### settle

```solidity
function settle(
    address[] memory tokens,
    uint256[] memory clearingPrices,
    TradeData[] memory trades,
    InteractionData[][3] memory interactions
) external
```

Executes a settlement batch with trades and interactions.

<ParamField path="tokens" type="address[]">
  Array of tokens involved in the settlement
</ParamField>

<ParamField path="clearingPrices" type="uint256[]">
  Clearing prices for each token
</ParamField>

<ParamField path="trades" type="TradeData[]">
  Array of trades to execute
</ParamField>

<ParamField path="interactions" type="InteractionData[][3]">
  Three-phase interaction array: [pre-interactions, intra-interactions, post-interactions]
</ParamField>

**COWFeeModule Usage:**
```solidity
// Module only uses intra-interactions (middle array)
InteractionData[][3] memory interactions = [
    new InteractionData[](0),      // Pre-interactions
    _interactions,                  // Intra-interactions (approvals, pre-sigs, etc.)
    new InteractionData[](0)        // Post-interactions
];
```

#### setPreSignature

```solidity
function setPreSignature(bytes calldata orderUid, bool signed) external
```

Sets or revokes a pre-signature for an order.

<ParamField path="orderUid" type="bytes">
  Unique identifier for the order (56 bytes: orderDigest + owner + validTo)
</ParamField>

<ParamField path="signed" type="bool">
  Whether to enable (true) or revoke (false) the pre-signature
</ParamField>

<Note>
  COWFeeModule always sets `signed = true` to enable orders for trading.
</Note>

#### domainSeparator

```solidity
function domainSeparator() external view returns (bytes32)
```

Returns the EIP-712 domain separator for the settlement contract.

**Returns:** `bytes32` - The domain separator used for order signatures

#### vaultRelayer

```solidity
function vaultRelayer() external view returns (address)
```

Returns the address of the vault relayer contract.

**Returns:** `address` - Vault relayer address that needs token approvals

<Note>
  The vault relayer is the contract that actually transfers tokens during order execution. All sell tokens must be approved to this address.
</Note>
