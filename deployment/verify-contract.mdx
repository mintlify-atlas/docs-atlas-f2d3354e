## Overview

Contract verification makes your contract's source code publicly available on block explorers, allowing users to read the contract code and verify its functionality. This guide covers how to verify the CoW Fee Module contract if automatic verification failed during deployment.

<Note>
  If you used the `--verify` flag during deployment and it succeeded, you don't need to verify again.
</Note>

## Prerequisites

- Deployed CoW Fee Module contract
- Block explorer API key (Etherscan, Gnosisscan, Arbiscan, etc.)
- All constructor parameters used during deployment
- Environment variables configured

## Verification Methods

### Method 1: Forge Verify (Recommended)

The easiest method is using Forge's built-in verification.

<Steps>
  <Step title="Load Environment Variables">
    Load your environment configuration:

    ```bash
    source .env
    ```
  </Step>

  <Step title="Prepare Constructor Arguments">
    Encode the constructor arguments that were used during deployment:

    ```bash
    # Generate ABI-encoded constructor arguments
    CONSTRUCTOR_ARGS=$(cast abi-encode \
      "constructor(address,address,address,address,bytes32,address,uint256)" \
      $SETTLEMENT \
      $TARGET_SAFE \
      $WRAPPED_NATIVE_TOKEN \
      $KEEPER \
      $APP_DATA \
      $RECEIVER \
      $MIN_OUT)

    echo "Constructor args: $CONSTRUCTOR_ARGS"
    ```

    <Note>
      These must exactly match the values used during deployment.
    </Note>
  </Step>

  <Step title="Verify Contract">
    Run the verification command:

    ```bash
    forge verify-contract \
      <fee-module-address> \
      COWFeeModule \
      --chain-id <chain-id> \
      --etherscan-api-key $ETHERSCAN_API_KEY \
      --constructor-args $CONSTRUCTOR_ARGS
    ```

    **Example for Ethereum Mainnet (Chain ID 1):**
    ```bash
    forge verify-contract \
      0x8429bf5bad17925c364c8c30a3c2a1e0d76602d2 \
      COWFeeModule \
      --chain-id 1 \
      --etherscan-api-key $ETHERSCAN_API_KEY \
      --constructor-args $CONSTRUCTOR_ARGS
    ```
  </Step>

  <Step title="Check Verification Status">
    After submission, Forge will provide a link to check the verification status on the block explorer. Wait a few moments and check if the "Contract" tab on the block explorer now shows the source code.
  </Step>
</Steps>

### Method 2: Complete Command (Single Line)

For convenience, here's a complete single-line command:

```bash
source .env && forge verify-contract \
  <fee-module-address> \
  COWFeeModule \
  --chain-id <chain-id> \
  --etherscan-api-key $ETHERSCAN_API_KEY \
  --constructor-args $(cast abi-encode "constructor(address,address,address,address,bytes32,address,uint256)" $SETTLEMENT $TARGET_SAFE $WRAPPED_NATIVE_TOKEN $KEEPER $APP_DATA $RECEIVER $MIN_OUT)
```

## Constructor Parameters Reference

The CoW Fee Module constructor requires these parameters in order:

1. **settlement** (`address`) - CoW Protocol settlement contract
2. **targetSafe** (`address`) - Safe where the module is enabled
3. **wrappedNativeToken** (`address`) - Token to convert fees into
4. **keeper** (`address`) - Authorized keeper account
5. **appData** (`bytes32`) - CoW order metadata hash
6. **receiver** (`address`) - Fee recipient address
7. **minOut** (`uint256`) - Minimum output amount in wei

## Verifying Constructor Arguments

If you're unsure about the constructor arguments, you can read them from the deployed contract:

```bash
source .env

# Read all constructor parameters
echo "Settlement: $(cast call $MODULE_ADDRESS 'settlement()' --rpc-url $RPC_URL)"
echo "Safe: $(cast call $MODULE_ADDRESS 'safe()' --rpc-url $RPC_URL)"
echo "Wrapped Native: $(cast call $MODULE_ADDRESS 'wrappedNativeToken()' --rpc-url $RPC_URL)"
echo "Keeper: $(cast call $MODULE_ADDRESS 'keeper()' --rpc-url $RPC_URL)"
echo "App Data: $(cast call $MODULE_ADDRESS 'appData()' --rpc-url $RPC_URL)"
echo "Receiver: $(cast call $MODULE_ADDRESS 'receiver()' --rpc-url $RPC_URL)"
echo "Min Out: $(cast call $MODULE_ADDRESS 'minOut()' --rpc-url $RPC_URL)"
```

## Troubleshooting

### Already Verified

```
Error: Contract already verified
```

**Solution**: The contract is already verified. Check the block explorer.

### Constructor Arguments Mismatch

```
Error: Constructor arguments mismatch
```

**Solution**: 
- Verify you're using the exact constructor arguments from deployment
- Read the values from the deployed contract and re-encode them
- Ensure byte order and formatting are correct

### Invalid API Key

```
Error: Invalid API Key
```

**Solution**: 
- Verify your `ETHERSCAN_API_KEY` is correct
- Ensure you're using the right API key for the network
- Check if the API key has verification permissions enabled

### Compilation Failed

```
Error: Compilation failed
```

**Solution**: 
- Ensure you're in the correct project directory
- Verify Foundry dependencies are installed (`forge install`)
- Check that the contract name is correct (`COWFeeModule`)

### Network Not Supported

```
Error: Chain not supported
```

**Solution**: Some networks may not support automatic verification. Check if the block explorer has a manual verification interface.

## Manual Verification (Alternative)

If automatic verification fails, you can verify manually through the block explorer:

<Steps>
  <Step title="Flatten Contract">
    Generate a flattened version of the contract:

    ```bash
    forge flatten src/COWFeeModule.sol > COWFeeModule-flat.sol
    ```
  </Step>

  <Step title="Navigate to Block Explorer">
    Go to your contract on the block explorer and find the "Verify & Publish" section.
  </Step>

  <Step title="Submit Verification">
    Fill in the verification form:
    - **Contract Address**: Your deployed module address
    - **Compiler Type**: Solidity (Single file)
    - **Compiler Version**: Match your `foundry.toml` settings
    - **Open Source License**: GPL-3.0-or-later
    - **Contract Source Code**: Paste contents of `COWFeeModule-flat.sol`
    - **Constructor Arguments**: Use the ABI-encoded args from earlier
    - **Optimization**: Enabled (if used in compilation)
  </Step>

  <Step title="Submit and Wait">
    Submit the form and wait for verification to complete.
  </Step>
</Steps>

## Verification Checklist

After successful verification, confirm:

- [ ] Source code is visible on block explorer
- [ ] Constructor arguments are displayed correctly
- [ ] Read functions show correct values
- [ ] Contract ABI is available
- [ ] Compiler version matches
- [ ] License is displayed

## Security Considerations

<Note>
  Verified contracts provide transparency and allow users to:
  - Read the contract code directly
  - Verify the contract behavior matches documentation
  - Interact with confidence knowing the code is auditable
  - Detect any discrepancies between deployment and source code
</Note>

Always verify contracts on production networks to maintain transparency and trust.
