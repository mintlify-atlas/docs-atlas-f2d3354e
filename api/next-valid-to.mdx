## Function Signature

```solidity
function nextValidTo() public view returns (uint32)
```

## Description

Calculates the deterministic `validTo` timestamp that will be used for orders created by the module. This function returns a timestamp aligned to hourly boundaries, specifically 2 hours into the future from the current hour's start.

<Note>
This function is deterministic and view-only, allowing scripts to predict order `validTo` values before executing the `drip` transaction onchain.
</Note>

## Returns

<ResponseField name="validTo" type="uint32">
  The Unix timestamp (in seconds) when orders will expire. This value is calculated as the start of the current hour plus 2 hours.
</ResponseField>

## Behavior

The function performs the following calculation:

1. Takes the current `block.timestamp`
2. Calculates the remainder when divided by 1 hour (3600 seconds)
3. Subtracts the remainder to get the start of the current hour
4. Adds 2 hours (7200 seconds) to get the expiration timestamp
5. Returns the result as a `uint32`

### Formula

```solidity
remainder = block.timestamp % 1 hours
validTo = (block.timestamp - remainder) + 2 hours
```

```solidity
function nextValidTo() public view returns (uint32) {
    uint256 remainder = block.timestamp % 1 hours;
    return uint32((block.timestamp - remainder) + 2 hours);
}
```

## Deterministic Nature

<Note>
The deterministic nature of this function is critical for off-chain order creation. Scripts can:
- Calculate the exact `validTo` timestamp before the transaction is mined
- Submit orders to CoW Protocol's API with matching `validTo` values
- Ensure presignatures match between off-chain and on-chain orders
</Note>

## Off-Chain Integration Example

```javascript
// Calculate nextValidTo off-chain (JavaScript/TypeScript)
function calculateNextValidTo(currentTimestamp) {
    const ONE_HOUR = 3600;
    const TWO_HOURS = 7200;
    
    const remainder = currentTimestamp % ONE_HOUR;
    const hourStart = currentTimestamp - remainder;
    const validTo = hourStart + TWO_HOURS;
    
    return validTo;
}

// Use in order submission
const now = Math.floor(Date.now() / 1000);
const validTo = calculateNextValidTo(now);

    // ... other order parameters
};
```

## Why 2-Hour Expiration?

Orders are given a 2-hour expiration window from the start of the current hour to:
- Provide sufficient time for order matching and settlement
- Align with CoW Protocol's batch auction timing
- Reduce the frequency of order recreation needed
- Maintain price validity while preventing stale orders
